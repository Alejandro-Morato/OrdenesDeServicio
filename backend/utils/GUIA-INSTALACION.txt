PASO 1: CONFIGURAR EL BACKEND
════════════════════════════════════════════════════════════════════════════

1. Crear carpeta del proyecto:
   mkdir inter-rural-sos
   cd inter-rural-sos
   mkdir backend

2. Copiar todos los archivos del backend a la carpeta backend/
   - Respetar la estructura de carpetas (api/, middleware/, utils/)

3. Crear archivo .env en backend/ con tus credenciales:

   SUPABASE_URL=https://ehoihmlbviviunsidisy.supabase.co
   SUPABASE_ANON_KEY=eyJhbGc...
   SUPABASE_SERVICE_KEY=[obtener de Supabase Settings > API > service_role key]

   CLOUDINARY_CLOUD_NAME=dtqn44tkx
   CLOUDINARY_API_KEY=524221722264325
   CLOUDINARY_API_SECRET=bh38OHxGpfFW1WqHr4zqiN5Hc8A

   PORT=3000
   NODE_ENV=development

4. Instalar dependencias:
   cd backend
   npm install

5. Ejecutar en desarrollo:
   npm run dev

   Deberías ver:
   🚀 Backend corriendo en http://localhost:3000

6. Probar que funciona:
   curl http://localhost:3000/api/health

   Respuesta esperada:
   {"status":"OK","timestamp":"2026-05-31T..."}

════════════════════════════════════════════════════════════════════════════
PASO 2: OBTENER SERVICE_ROLE KEY DE SUPABASE
════════════════════════════════════════════════════════════════════════════

El backend necesita el SERVICE_ROLE KEY (no el anon key).

1. Ve a tu proyecto en Supabase
2. Settings (⚙️) → API
3. En "Project API keys" busca:

   service_role secret (⚠️ NUNCA expongas esta key en el frontend)

4. Cópiala y pégala en .env como SUPABASE_SERVICE_KEY

════════════════════════════════════════════════════════════════════════════
PASO 3: PROBAR LA API
════════════════════════════════════════════════════════════════════════════

Todas las rutas requieren autenticación. Primero obtén un token:

1. Desde el frontend (que ya tienes), haz login
2. Captura el token de Supabase desde las DevTools:

   sessionStorage.getItem('supabase.auth.token')

3. Usa ese token en las peticiones al backend:

   curl -H "Authorization: Bearer TU-TOKEN-AQUI" \
        http://localhost:3000/api/ordenes

════════════════════════════════════════════════════════════════════════════
RUTAS DISPONIBLES
════════════════════════════════════════════════════════════════════════════

📋 ÓRDENES
GET    /api/ordenes              Listar órdenes
GET    /api/ordenes/:id          Detalle de orden
POST   /api/ordenes              Crear orden (taller)
PATCH  /api/ordenes/:id          Actualizar orden
DELETE /api/ordenes/:id          Eliminar (gerencia)

🔧 PIEZAS
GET    /api/piezas/:ordenId      Piezas de una orden
POST   /api/piezas               Agregar pieza (refacciones)
PATCH  /api/piezas/:id           Actualizar pieza
DELETE /api/piezas/:id           Eliminar pieza

💰 GASTOS
GET    /api/gastos/:ordenId      Gastos de una orden
POST   /api/gastos               Agregar gasto (refacciones)
DELETE /api/gastos/:id           Eliminar gasto

📊 REPORTES
GET    /api/reportes/mano-obra?mes=5&anio=2026   Reporte mano obra
GET    /api/reportes/general                     Stats generales

DEPLOY EN VERCEL (cuando esté listo)
════════════════════════════════════════════════════════════════════════════

1. Instalar Vercel CLI:
   npm i -g vercel

2. Hacer login:
   vercel login

3. Desde la carpeta backend/:
   vercel --prod

4. Configurar variables de entorno en Vercel dashboard:
   Settings → Environment Variables → agregar todas las de .env

5. Tu API estará en:
   https://tu-proyecto.vercel.app/api/ordenes
